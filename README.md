# Практическая работа №3 — конфигурационное управление

**Вариант №34, этапы 1–4.** Ассемблер и интерпретатор учебной
виртуальной машины (УВМ). Этап 5 не выполняется.

Язык реализации — Python 3.10+. Дополнительные библиотеки не нужны.
Проект запускается из его корневой папки (там, где находится README.md).

## 1. Общая информация

У виртуальной машины один регистр-аккумулятор. Программа записывается
текстовыми командами и переводится ассемблером в бинарный файл.
Интерпретатор читает бинарный файл и исполняет команды последовательно.
Память команд и память данных **разделены**.

## 2. Язык ассемблера и машинное представление

| Команда | Поле A | Поле B | Длина | Описание |
|---|---:|---|---:|---|
| `LOAD n` | 87 | константа (18 бит) | 4 байта | аккумулятор = n |
| `READ` | 63 | отсутствует | 1 байт | аккумулятор = память[аккумулятор] |
| `STORE addr` | 39 | адрес (29 бит) | 5 байт | память[addr] = аккумулятор |
| `OR addr` | 1 | адрес (29 бит) | 5 байт | аккумулятор = аккумулятор OR память[addr] |

Синтаксис напоминает традиционный ассемблер. Каждая команда находится на
своей строке; регистр букв не важен. Числа записываются десятичными, либо
с префиксом `0x` (шестнадцатеричные), `0b` (двоичные), `0o` (восьмеричные).
Комментарии начинаются с `#` или `;`. Пустые строки игнорируются.

```asm
; Сохраняем число 12 в ячейку 300
LOAD 12
STORE 300
LOAD 10
OR 300
STORE 301
```

В машинном коде поле `A` занимает младшие 7 бит, а поле `B` начинается
с бита 7. При упаковке используется **little-endian**. Ассемблер
проверяет допустимые диапазоны чисел: константа — от 0 до 262143;
адрес — от 0 до 536870911. Зарезервированные биты в коде нулевые.

## 4. Как запустить (Windows, VS Code или терминал)

Открыть папку проекта, затем **Терминал → Создать терминал**.
Выполнить команды ниже в корне проекта.

### Этапы 1–2: разбор программы и машинный код

```powershell
python -m src.assembler examples/spec_tests.asm build/spec_tests.bin --test
```

В режиме `--test` показываются промежуточные поля `A`, `B` и байты.
Эталонные результаты из методички (стр. 140–141):

```text
LOAD 180  -> A=87, B=180 -> 0x57, 0x5A, 0x00, 0x00
READ      -> A=63        -> 0x3F
STORE 643 -> A=39, B=643 -> 0xA7, 0x41, 0x01, 0x00, 0x00
OR 410    -> A=1,  B=410 -> 0x01, 0xCD, 0x00, 0x00, 0x00
```

Размер полученного файла `build/spec_tests.bin` — **15 байт**.

### Этап 3: копирование массива

```powershell
python -m src.assembler examples/copy_array.asm build/copy_array.bin
python -m src.interpreter build/copy_array.bin build/copy_array.csv --start 100 --end 105
```

Сначала записываются исходные данные `[10, 20, 30]` по адресам
`100–102`. Затем каждое значение копируется в ячейки `103–105`.
Конечный CSV-файл `build/copy_array.csv` должен содержать:

```csv
address,value
100,10
101,20
102,30
103,10
104,20
105,30
```

### Этап 4: побитовое «ИЛИ»

```powershell
python -m src.assembler examples/bitwise_or.asm build/bitwise_or.bin
python -m src.interpreter build/bitwise_or.bin build/bitwise_or.csv --start 300 --end 301
```

В аккумуляторе находится `10` (`1010`), в ячейке 300 — `12` (`1100`).
Побитовое ИЛИ даёт `1110`, то есть **14**. Результат сохраняется
в ячейку 301. Файл `build/bitwise_or.csv`:

```csv
address,value
300,12
301,14
```

### Все автоматические тесты

```powershell
python -m unittest discover -s tests -v
```

В PowerShell (Windows) можно запускать готовые сценарии:

```powershell
./run.bat spec
./run.bat copy
./run.bat or
./run.bat test
```

В Linux/macOS: `sh run.sh spec`, `sh run.sh copy`, `sh run.sh or`,
`sh run.sh test`.

## 5. Что делает интерпретатор

1. Получает путь к `.bin`, путь к CSV-файлу и границы дампа (`--start`
   и `--end`, обе границы включены).
2. Загружает байты программы в отдельную память команд.
3. Читает очередную инструкцию, выделяя код `A` и операнд `B`.
4. Выполняет действие над аккумулятором и словарём памяти данных.
5. После исполнения записывает выбранный диапазон памяти в CSV.

Ячейки памяти данных изначально равны нулю. Словарь хранит только явно
записанные ячейки: это позволяет поддерживать 29-битные адреса без
выделения огромного массива. Ошибки в коде команд и недопустимые адреса
проверяются. После исполнения печатается количество команд.

## 6. Настройки командной строки

Ассемблер:

```text

```

```text

```

Оба приложения имеют встроенную справку: добавить `--help`.

## 7. Этапы и Git

В проекте подготовлены четыре последовательных коммита:

1. `feat(stage1): parse assembly into intermediate instructions`
2. `feat(stage2): assemble little-endian binary instructions`
3. `feat(stage3): interpret basic commands and dump data memory`
4. `feat(stage4): add bitwise OR and ALU tests`

Посмотреть историю:

```bash
git log --oneline
```

Отправка в созданный публичный репозиторий GitHub:

```bash
git remote add origin https://github.com/USERNAME/REPO.git
git branch -M main
git push -u origin main
```

Перед публикацией замените `USERNAME` и `REPO` своими.
В предоставленной локальной истории автор коммитов указан как
`Student <student@example.local>` — это заглушка; при необходимости
измените автора коммитов на свои реальные данные до сдачи. Бинарные файлы, дампы,
временные файлы Python и файлы редакторов исключены через `.gitignore`.
