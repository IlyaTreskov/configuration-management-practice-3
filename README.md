# Конфигурационное управление — практическая работа №3

**Вариант 34.** Ассемблер и интерпретатор учебной виртуальной машины.

Программа использует один регистр-аккумулятор. Исходный язык похож на
традиционный ассемблер: `МНЕМОНИКА ЧИСЛО`; комментарии после `#` или `;`.

| Мнемоника | Код A | Операнд B | Байтов | Действие |
|---|---:|---|---:|---|
| `LOAD n` | 87 | константа, 18 бит | 4 | аккумулятор = n |
| `READ` | 63 | нет | 1 | аккумулятор = память[аккумулятор] |
| `STORE addr` | 39 | адрес, 29 бит | 5 | память[addr] = аккумулятор |
| `OR addr` | 1 | адрес, 29 бит | 5 | аккумулятор |= память[addr] |

## Этапы 1–2: ассемблер

Программа считывает файл, разбирает команды во внутреннее представление
`Instruction`, а затем объединяет поля `A` и `B` в двоичные слова
(little-endian, `A` занимает 7 младших бит).

```bash
python -m src.assembler examples/spec_tests.asm build/spec_tests.bin --test
python -m unittest discover -s tests -v
```

Результат эталонного примера: 15 байт. Проверяемые последовательности:

```text
LOAD 180  -> 0x57, 0x5A, 0x00, 0x00
READ      -> 0x3F
STORE 643 -> 0xA7, 0x41, 0x01, 0x00, 0x00
OR 410    -> 0x01, 0xCD, 0x00, 0x00, 0x00
```

Интерпретатор будет добавлен в третьем этапе.
