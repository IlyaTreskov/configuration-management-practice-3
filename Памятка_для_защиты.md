# Как объяснить практическую №3, вариант 34

**Общая суть:** я создал учебную виртуальную машину. Ассемблер переводит
понятные человеку команды в байты, а интерпретатор выполняет эти байты.
Выполнены этапы с первого по четвёртый; пятый этап не выполнялся.

**Этап 1:** я придумал простой синтаксис `LOAD число`, `READ`,
`STORE адрес`, `OR адрес`. Функция `parse_source` считывает исходник и
получает список объектов `Instruction`. Функция `parse_line` разбирает
отдельную команду. В `--test` видно поля A и B.

**Этап 2:** функция `encode_instruction` записывает числовые поля
команды в машинное представление. У операции семь младших бит.
Например, `LOAD 180` становится `57 5A 00 00` в шестнадцатеричном виде.
Результат сохраняется в `.bin`. Все тестовые последовательности из
методички полностью совпадают.

**Этап 3:** `Machine` содержит аккумулятор, указатель команды `pc`
и память данных. Машинные инструкции хранятся в `program` отдельно.
В цикле `run()` каждая команда считывается, распознаётся и выполняется.
`LOAD` загружает значение, `READ` читает из памяти по адресу в
аккумуляторе, `STORE` сохраняет аккумулятор по адресу из команды.
Проверка — копирование `[10, 20, 30]` из ячеек 100–102 в 103–105.
Дамп сохраняется в CSV-файл.

**Этап 4:** добавил побитовое ИЛИ. Оно сравнивает биты двух чисел:
`1100 OR 1010 = 1110`, то есть `12 | 10 = 14`. Полученное значение
записывается в память 301. Автоматический тест это проверяет.

## Что открыть на защите

1. `src/specification.py` — коды и размеры команд варианта.
2. `src/assembler.py` — как строка превращается в команду.
3. `src/machine_code.py` — как поля превращаются в байты и обратно.
4. `src/interpreter.py` — память, аккумулятор, цикл исполнения.
5. `examples/copy_array.asm`, `examples/bitwise_or.asm` — примеры.
6. `build/copy_array.csv`, `build/bitwise_or.csv` — дампы после запуска.
7. Терминал — команды `./run.bat spec`, `./run.bat copy`, `./run.bat or`,
   `./run.bat test`, `git log --oneline`.

## Возможные вопросы

**Что такое аккумулятор?** Один регистр, в котором хранятся
промежуточные значения для выполнения команд.

**Что такое ассемблер?** Переводчик команд `LOAD`, `STORE` и других
в машинные байты.

**Что такое интерпретатор?** Программа, которая читает готовые
машинные команды и выполняет соответствующие действия.

**Почему память программы и данных разделена?** Этого требует вариант 34;
запись данных не должна менять машинный код исполняемой программы.

**Что такое дамп?** Выгрузка содержимого выбранных ячеек памяти в CSV.

**Зачем тесты?** Чтобы подтвердить совпадение эталонных байтов,
корректное копирование массива и работу `OR`.

**Почему четыре коммита?** Каждый из четырёх этапов должен быть
отражён отдельным изменением Git, чтобы было видно развитие проекта.
